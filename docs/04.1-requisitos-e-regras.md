# 📋 4.1 Requisitos e regras de negócio

> **FONTE** Requisitos extraídos do guia da atividade e conferidos no código da branch `main` (commit `382c379`). ✅ = implementado; 🗺️ = planejado, ainda não existe na solution.

## 4.1.1 Contexto e atores

| Ator | Tipo | Descrição |
|---|---|---|
| 🎓 Usuário (estudante) | Principal | Pessoa que organiza a lista de videoaulas. Acessa a API **por meio do frontend web** (ou de qualquer cliente HTTP). |
| 🌐 YouTube Data API v3 | Secundário (sistema externo) | Serviço do Google que fornece título, canal, miniatura e duração a partir do ID do vídeo. |

Não há autenticação: a lista é única e fica no arquivo SQLite da API.

## 4.1.3 Requisitos não funcionais (RNF)

| ID | Característica (ISO/IEC 25010) | Requisito | Como aparece no código |
|---|---|---|---|
| RNF01 | Portabilidade | Desenvolver e executar em Windows, macOS e Linux. | .NET 10 multiplataforma, SQLite em arquivo; CI roda em `ubuntu-latest` e `windows-latest`. |
| RNF02 | Manutenibilidade — modularidade | Separar domínio, aplicação, infraestrutura e apresentação (DDD). | Quatro projetos com dependências unidirecionais; o domínio não referencia EF Core nem ASP.NET. |
| RNF03 | Manutenibilidade — testabilidade | Testar regras e persistência automaticamente com NUnit. | `StudyTube.Tests`: 19 testes unitários e 4 de integração (SQLite `:memory:`). |
| RNF04 | Segurança — confidencialidade | Manter a chave da YouTube Data API fora do controle de versão e fora do frontend. | `YouTube:ApiKey` via User Secrets; a chamada ao Google é feita só pelo backend; `*.db` no `.gitignore`. |
| RNF05 | Compatibilidade — interoperabilidade | Expor contrato HTTP/JSON documentado. | JSON em `camelCase`; OpenAPI em `/openapi/v1.json` e Swagger UI em `/swagger` (ambiente `Development`). |
| RNF06 | Eficiência de desempenho | Ser adequado a uma lista pessoal local. | SQLite local e uma única chamada ao Google por vídeo novo (a verificação de duplicidade acontece antes da chamada). |
| RNF07 | Confiabilidade — integridade | Impedir duplicidade também no banco. | Índice único em `Videos.YouTubeId` (`VideoConfiguration`). |

## 4.1.4 Regras de negócio (RN)

| ID | Regra | Onde é aplicada | Mensagem / efeito |
|---|---|---|---|
| RN01 | O ID do vídeo deve ter exatamente 11 caracteres entre `A–Z`, `a–z`, `0–9`, `_` e `-`. | `YouTubeVideoId.Create` | `ID do YouTube inválido.` |
| RN02 | A URL deve ser absoluta e de vídeo do YouTube: host `youtu.be` (ID no caminho) ou `youtube.com`, `www.youtube.com`, `m.youtube.com` com `/watch?v=`, `/embed/` ou `/shorts/`. | `YouTubeVideoId.FromUrl` | `URL inválida.` (não absoluta) ou `Não é uma URL de vídeo do YouTube.` |
| RN03 | O título é obrigatório (não nulo, não vazio, não só espaços). | `Video.Create` | `O título é obrigatório.` |
| RN04 | A duração não pode ser negativa. | `Video.Create` | `A duração não pode ser negativa.` |
| RN05 | O mesmo vídeo (`YouTubeId`) não pode estar duas vezes na lista. | `VideoService.AddFromUrlAsync` + índice único | `Este vídeo já está na sua lista.` |
| RN06 | Não é permitido marcar como assistido um vídeo já assistido. | `Video.MarkAsWatched` | `Este vídeo já foi marcado como assistido.` |
| RN07 | Desmarcar define `Watched = false` e `WatchedAt = null` e é permitido mesmo se o vídeo já estiver desmarcado. | `Video.MarkAsUnwatched` | Sem erro. |
| RN08 | Toda videoaula nasce não assistida (`Watched = false`, `WatchedAt = null`), com `AddedAt` em UTC e título/canal sem espaços nas pontas. | `Video.Create` | — |
| RN09 | Se o YouTube não devolver o vídeo, a inclusão falha. | `VideoService.AddFromUrlAsync` | `Vídeo não encontrado no YouTube.` |

As regras são referenciadas pelos fluxos de exceção (FE) dos [casos de uso](04.2-casos-de-uso.md). A validação do frontend melhora a experiência, mas **não substitui** estas regras.

> **REGRA ≠ FUNCIONALIDADE** Uma regra pode ser atendida por mais de um caso de uso (RN02 vale para UC_001 e UC_007) e um caso de uso pode atender várias regras.
